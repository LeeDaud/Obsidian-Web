# Echo Android 独立 App 需求文档

版本：0.1（已确认需求） · 日期：2026-10-08 · 状态：用户已确认实施，本地实现/验证完成，设备和真实仓库验收待执行。

用户在文档评审后回复“实施”，授权本地原生实现与合成验证。此授权不包含真实笔记迁移、真实仓库联调、现有文件删除或公开发布。实施入口见 [plan.md](plan.md)，技术方案见 [android-architecture.md](android-architecture.md)，当前交付与验收限制见 [Android 指南](../setup/android.md)。

## 1. 产品目标

将当前手机记录能力迁移为可安装、在手机本地运行的 Android App。安装后即能创建、编辑、查看和暂存笔记；配置用户自己的 GitHub 仓库后，手机直接投递 Markdown 与附件，电脑继续使用现有方式接收。

首版只迁移当前记录流程和必要的配置能力，不接入 ObsidianHub。ObsidianHub 已是支持 Windows 的仓库管理、跨库链接和工作流工具，其后续接入不构成本阶段的依赖。

此前 `apps/android/` 的 APK 是加载远端 Memos 的 WebView 容器原型。其构建、签名和策略测试仅证明容器可编译，不满足本需求；不能再以安装了 APK 作为迁移完成的依据。

### 成功判定

1. 全新安装、飞行模式、未配置 GitHub时，记录界面仍能打开，正文和附件仍可保存并重开恢复。
2. 阻断 `memos.leedaud.xyz` 与 `echo.leedaud.xyz` 后，核心功能保持可用；连接 GitHub 后可直接完成投递。
3. 笔记内容、编辑状态、投递队列和回执在 App 本地持久化；关闭界面不导致已保存任务消失。
4. GitHub 中正文及全部附件在同一个提交中发布并核验；不覆盖其他设备的改动。
5. 用户无需部署 Memos/Echo 服务或让电脑保持在线。GitHub 不可达时只影响投递，不影响本地记录。

## 2. 首版范围与功能对应

“已有功能”以当前项目的手机个人记录工作流为基线，不要求完整复制 Memos 的多人社区、管理后台或完整 Obsidian 运行时。

| 编号 | 当前能力 | Android 首版要求 |
| --- | --- | --- |
| F01 | 手机列表、详情、编辑器 | 本地运行；按 2026-10-08 已确认 UI 重构计划逐页复刻当前 Memos 手机网页，不以通用 Compose 布局代替 |
| F02 | 笔记 / 待办选择 | 两项整行等宽；保留 Markdown checkbox 与已有 YAML 导出语义 |
| F03 | 设备草稿、暂存、保存 | 输入写本机草稿；暂存不投递；保存持久化正式版本并按授权创建投递任务 |
| F04 | 图片及其他已有附件 | 系统选择、复制至 App 私有存储、离线预览；正文与附件一起投递 |
| F05 | 已保存 / 投递中 / 已投递 | 状态位于时间戳旁；错误、冲突、等待和核验回执可查看 |
| F06 | 未投递编辑、已投递续写 | 未入队笔记编辑原记录；入队或已核验笔记创建关联续写，保护原快照 |
| F07 | 显式补投 / 重试 | 使用原任务或明确新任务，重复操作不重复发布；不自动补投全部历史记录 |
| F08 | 时间戳路径、附件归档 | 保留上海时区命名、同秒顺延、相对路径及 WikiLink 续写格式 |
| F09 | 日历、搜索、标签、置顶、归档 | 操作本机可见记录；保持已有用途，不扩展为全仓库搜索或跨设备同步 |
| F10 | 复制、分享、文件/图片导出 | 由系统分享/文件选择器处理；仅用户显式操作才导出私人内容 |
| F11 | 已有录音、位置元数据 | 保留录音附件及位置记录入口；权限按需请求，拒绝不阻断正文保存 |
| F12 | 浅色/深色与手机操作 | 原网页主题、尺寸、间距和图标为视觉基线，逐尺寸截图对照；适配系统键盘、返回手势、安全区和字体缩放，未验证的差异不宣称一致 |
| F13 | 原服务器持有 GitHub 凭据 | 改为设备配置一个目标仓库、分支和用户授权；配置是直投所必需的迁移适配 |

地图底图、地址解析、外部链接等原有在线辅助能力允许继续依赖相应外部服务；必须与核心离线记录解耦，坐标与已录入内容仍可本地查看。不得让底图加载失败阻止保存。

### 不在本阶段实现

- ObsidianHub 连接、跨库工作流、索引或电脑逐条接收回执。
- iOS、桌面 App、新的服务端、Memos/Echo 本机服务模拟或远端页面容器作为主界面。
- 克隆完整 Git 仓库、Git 历史浏览、从 GitHub 下载整个知识库、多设备双向合并。
- 多用户社区、评论协作、公开分享站点、账号管理后台、AI 功能、额外推送和常驻同步服务。
- 自动清理已投递本地笔记、自动删除 GitHub 文件、自动迁移旧服务数据、停用或删除现有服务。
- 首版自行创建 GitHub 仓库/分支、配置组织规则或修改分支保护。用户提供已有目标仓库和分支。

## 3. 用户流程

### 3.1 首次启动

进入本地记录界面，不等待 Memos 登录或网络请求。无需授权即可写笔记；GitHub 尚未配置时，保存仅写本机，详情说明“尚未配置仓库”，不伪装为已入队。GitHub 配置不与本地记录绑定，不需要用户先输入服务器域名。

### 3.2 配置 GitHub

首版建议通过设备内配置页录入 GitHub.com 的仓库所有者、仓库名、已有分支及用户自行创建的细粒度 token。令牌只授权目标仓库所需的 Contents 读写；需要组织批准、令牌失效或分支保护阻止写入时明确反馈。该授权方案为建议方案，确认后实施。[GitHub token 管理](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)

“检查连接”只读检查身份、仓库和分支，不能偷偷创建测试文件；只读检查通过也不能宣称真实写入已验证。首次真正投递才验证写入能力。令牌权限按仓库授予，不应把 App 的目录限制宣传为 GitHub 提供的文件夹权限隔离。[GitHub 权限说明](https://docs.github.com/en/rest/authentication/permissions-required-for-fine-grained-personal-access-tokens)

配置成功后由用户显式开启投递，配置动作本身不投递既有笔记。关闭投递保留本地内容与任务；已开始的网络写入须完成结果核验或标记不确定，不能宣称必然撤回。更换目标时不将原队列静默转投其他仓库。

不复用或下发现有服务器的 GitHub/bridge token。首版无需 Memos 登录；未来友好的 GitHub 登录授权另行规划，不嵌入 OAuth 客户端密钥。

### 3.3 编辑、暂存与保存

| 操作 | 本地结果 | 网络行为 |
| --- | --- | --- |
| 输入、切换应用、返回、退出 | 自动保留设备草稿，成功落盘后才显示草稿已保留 | 不创建投递任务 |
| 暂存 | 立即持久化当前正文、待办状态与附件引用 | 不上传、不入队 |
| 保存（未配置/未启用投递） | 保存正式本地版本，显示已保存 | 不投递；之后需显式补投 |
| 保存（已配置并启用投递） | 本地保存成功后生成不可变快照和持久任务 | 在线尝试直投，离线等待 |
| 补投、重试 | 复用当前版本已有任务，或显式创建该版本任务 | 仅处理该授权版本 |
| 联网、后台恢复、设备重启 | 恢复既有授权任务，不改变草稿内容 | 可重试已入队快照，不自动上传草稿 |

保存入口应清楚表达当前是否会投递（如已启用时显示“保存并投递”或等效明确说明），不能仅凭用户配置了 token 推定其授权所有历史上传。空白且无附件的记录不生成正式 Markdown 或投递任务。

持续输入采用短延迟本地草稿持久化；暂存/保存立即执行。进程强杀时承诺恢复最后一次已确认持久化的版本，不虚构“任何尚未落盘字符永不丢失”。应用恢复必须区分草稿与已入队快照，不让旧队列覆盖新草稿。

### 3.4 状态和续写

保留三种主状态，设备草稿另外提示，不计为正式投递成功。

| 主状态 | 含义 | 编辑与详情 |
| --- | --- | --- |
| 已保存 | 正式版本已在本机持久化，尚未入队；或入队失败/冲突/待处理 | 未入队可编辑原笔记；失败任务虽显示已保存，也必须保留冻结保护，详情解释原因 |
| 投递中 | 当前快照已授权且未完成核验，包括离线、排队、等父笔记、待确认 | 创建关联新笔记续写；不宣称 worker 持续实时运行 |
| 已投递 | 当前对应快照已在目标分支发布并完成正文/附件核验 | 创建关联新笔记续写；显示路径、提交和核验时间，隐藏重复投递菜单 |

状态未知或提交结果不确定时先保护原快照，不能因网络失败回退到可任意覆盖状态。编辑资格取决于持久记录是否冻结/曾发布，不能只判断标签文字。

续写保存为独立笔记，保留单一父笔记标识。父任务未核验时子任务等待；父路径最终确定后生成 `续写自：[[父文件名]]`。父任务失败时保留子内容并提示，不生成错误链接或修改父文件；父子必须属于同一目标仓库/分支绑定。

已核验回执在离线时仍可查看，注明核验时间；它证明该次发布成功，不宣称远端文件之后始终未变，也不表示电脑 Obsidian 已拉取。

## 4. 数据与文件兼容要求

正式保存的正文使用 UTF-8 Markdown 文件，本地数据库负责草稿、索引、版本、任务和回执；实际字节、附件与索引一致性是验收内容。所有运行时私人内容位于手机 App 私有目录，不在电脑源码目录生成真实笔记。

GitHub 新笔记默认固定写入 `00_Inbox/`，新附件写入 `attachments/<最终笔记名>/`。首版不增加目录模板系统。示例：

```text
00_Inbox/20261008-143000.md
attachments/20261008-143000/20261008-142959.png
```

正文中的图片引用为 `![](../attachments/20261008-143000/20261008-142959.png)`。文件名按 Asia/Shanghai 格式化；同秒新笔记按秒顺延，同秒同扩展名附件以稳定顺序附加 `-02` 等序号。内部使用独立稳定 ID，不能只靠时间戳识别笔记；一旦发布候选提交，先查清该次结果，再允许重新分配路径。

已有历史文件不改名、不移动、不补写链接。待办沿用 `type`、`status`、`created`、`source` 元数据及当前 checkbox 判定；新 Android 记录的 `source` 建议为 `echo-android`，不得假称来源是 Memos。普通笔记不强加待办元数据。

沿用现有投递容量边界：最终 Markdown ≤256 KiB、每个附件 ≤10 MiB、附件总计 ≤25 MiB、最多 100 个附件。超限在本地明确提示并保留草稿，不能到一半才丢失数据。上一容器原型的 20 MB 导出限制不是本次需求依据。

附件选中后复制到私有目录并核验，不能依赖临时 content URI 在重启后仍有效。失败不生成假引用；当前编辑、已保存版本、任务或回执仍引用的文件不自动回收。未投递内容不按时间自动删除。

本地归档/删除不会传播为 GitHub 删除。活动或不确定投递任务中的笔记不得直接物理删除；允许的删除操作须先解释作用域并处理任务，不销毁恢复依据。已投递记录默认继续保留在本机，不承接服务器临时正文自动清理策略。

## 5. GitHub 直接投递要求

- 私有仓库可用，不通过 Memos/Echo代理正文、附件或 token。
- 正文和附件组成同一 Git tree/commit，以非强制更新发布到分支；不能逐文件提交后提前报成功。GitHub reference API 提供非强制更新能力。[Git references](https://docs.github.com/en/rest/git/refs)
- 按仓库/分支串行处理本机任务；其他设备推进分支时重新读取当前 head并检查路径，不能覆盖其提交。
- 路径已存在、大小写冲突、目录/符号链接冲突或曾投递文件被移动/删除时保护数据；不静默覆盖，不自动复活远端已移走文件。
- 相同授权快照重试至多形成一次有效发布；提交回执丢失或进程崩溃时先核验已持久化尝试，再决定是否重发。
- 只有确认提交已发布到目标分支历史，并逐项核验 Markdown 和全部附件后才显示已投递；仅创建了孤立 commit 不算成功。
- 网络超时、限流、身份失效、权限不足、规则拒绝与冲突分开处理；需要重新授权的问题不无限重试。等待限流时遵守服务端重试时间。[GitHub API 故障处理](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api)

Android 后台调度受系统和厂商限制。首版使用可恢复任务，不承诺锁屏后即刻完成或强制停止后仍继续执行；重新打开 App可恢复已授权队列。WorkManager支持持久任务与网络条件，但不是实时执行保证。[Android 持久任务](https://developer.android.com/develop/background-work/background-tasks/persistent)

## 6. 隐私、授权与非功能要求

手机保存用户自己的 GitHub 授权；使用 Android Keystore 保护加密密钥，再加密保存 token，不把 token 直接明文写入数据库、日志、APK 或截图。Keystore保护的是密钥，不能据此宣称整个 App 数据库已经加密。[Android Keystore](https://developer.android.com/privacy-and-security/keystore)

本地 Markdown/附件默认由 App 私有目录和 Android 系统隔离保护；首版不宣称端到端加密或全部笔记自行加密。GitHub 保存可读 Markdown/附件，用户应使用私有输入仓库。日志不包含私人正文、完整授权头或附件内容；关闭系统云备份中凭据和私人数据的自动搬运。

支持 Android 8.0及以上为建议兼容基线，最低和当前目标 API 均须实际验证。触控目标至少 44dp；测试 320/390/430dp 等效宽度、软键盘、安全区、深浅主题、系统字体缩放和中文组合输入。新增界面执行 ss-review；已有交互视觉优先，不重做无关仪表盘。

性能目标在实现前固定测试设备：普通正文约 10 KiB、本地 1,000 条笔记时，冷启动到可编辑目标 ≤2 秒，本地列表首次可操作目标 ≤1 秒；所有网络、附件复制与导出不阻塞主线程。这些是待测目标，不是当前成绩。

## 7. 旧数据与交付边界

现有浏览器草稿、WebView 原型草稿、服务器 Memo 和 GitHub 历史不自动成为原生 App 本地数据。首版核心验收使用 App 新建记录；完整历史迁移是单独批次，需明确来源、重复识别、续写映射与授权，再执行只读导入。导入历史不得自动创建投递任务。

当前 Web 服务在迁移期间继续运行，作为旧数据访问入口。用户最终选定切换后再单独讨论服务停用、原型删除和数据清理。本需求不会追溯授权上述动作。

交付包括 Android 源码、可安装 APK、配置/安装说明、功能对照表和实际测试记录。测试 APK与正式发行包必须区分；正式签名密钥、代码提交推送、公开分发及真实仓库联调分别授权。现有 CI/CD 本轮不调整。

## 8. 验收矩阵

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| A01 | 首次安装，飞行模式，无 GitHub 配置 | 本地界面、编辑、暂存、保存和列表可用，不要求服务器登录 |
| A02 | 屏蔽 Memos/Echo，仅放通 GitHub | 新建、附件、直投和回执可用；核心流程无自有服务器请求 |
| A03 | 输入/暂存后联网、锁屏、退出 | 无新投递任务，无草稿上传；已确认暂存内容重开存在 |
| A04 | 离线保存并投递，杀进程后重开联网 | 授权快照可恢复并投递，未保存后续草稿不被带上 |
| A05 | 连点保存/重试、系统 worker 重复执行 | 同一快照只发布一次，路径和回执一致 |
| A06 | 图片/普通附件、录音、位置记录 | 本地可用；拒绝权限可继续正文编辑；允许的附件与正文同提交 |
| A07 | 分支更新成功但响应丢失；关键步骤崩溃 | 能查明已发布尝试，不重复生成笔记或误报失败后覆盖 |
| A08 | 两设备同秒建笔记或同时推进分支 | 无覆盖、无强推；路径冲突可顺延或明确待处理 |
| A09 | 父任务未完成，子笔记已保存 | 子任务等待；父核验后使用最终路径续写，父文件不变 |
| A10 | token失效/权限不足/限流/分支保护 | 草稿和任务保留，详情准确，授权错误无无限重试 |
| A11 | 已投递路径被电脑改写、移动或删除 | 不回写旧文件，不传播删除或复活旧路径 |
| A12 | 保存、任务、附件落盘时磁盘满或中断 | 无假成功、无悬空引用；能恢复已确认版本或明确指出故障 |
| A13 | 更换仓库或撤销投递 | 原任务仍绑定原目标；无静默改投，活动结果可核验 |
