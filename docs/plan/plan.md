### 3. 架构、接口与数据职责

采用固定上游版本加最小前后端补丁，Memos 与 Echo 独立进程/容器。服务间走受限通道，不直接读取或跨进程修改 Memos 数据库。Memos 的创建、编辑、附件变更与清理必须由同一服务端版本协议协调；未受保护的写入入口不得绕过协议。

逻辑接口在阶段一细化并测试，以下不是已存在的上游接口：
- 提交快照：认证用户、实例/笔记标识、幂等请求 ID、预期版本、正文和附件清单；返回稳定的 submission ID 与版本摘要。
- 查询状态：按用户权限返回提交状态、已核验版本与冲突原因，不返回凭据。
- 编辑会话：打开编辑器先取得会话标识和 fencing token；心跳只续会话，结束会话显式释放。旧 token 的写入被拒绝，设备草稿仍可恢复。
- 条件清理：提交已核验凭证及预期版本，由 Memos 服务端在事务/等效原子机制中同时检查版本、会话、退休状态后推进清理，不使用无条件 DELETE 拼接查询实现。

提交记录至少包括：实例与笔记稳定标识、提交 ID、单调版本、正文摘要、附件清单摘要、目标路径、预期远端 blob、GitHub attempt/commit、重试状态。不可用秒级更新时间作为唯一版本。设备会话记录与投递状态分离；清理后只留不含正文/附件的必要去重与退休元数据。

队列以显式提交记录为权威，分页扫描未完成提交用于恢复；不扫描普通笔记然后默认授权上传。先轮询恢复可靠队列，后续 Webhook 只做唤醒加速，不能依赖 webhook 唯一投递。重复、乱序与漏事件均应可恢复。

### 4. Markdown、附件与 GitHub 策略

- 一条笔记对应一个稳定路径，建议 Memos/yyyyMMdd-HHmmss.md，上海时区；同秒冲突用现有递增秒数分配方式，真实创建时间放元数据，路径首次分配后不随编辑改变。Memos/ 仅由接入程序创建新内容，不删除用户整理后的内容。
- 附件建议 attachments/memos/<稳定笔记标识>/<内容摘要>.<校验后扩展名>；文件名与路径由程序生成，拒绝路径穿越。Markdown 使用相对附件链接，不依赖登录态或临时远程地址。
- 元数据保存来源标识、创建时间和提交版本。标签保留正文语义；首期只承诺 Markdown 正文与已关联附件，不默默丢弃评论/关系等额外信息，发现未覆盖类型时提示其不在投递范围。
- 扩展 GitHubRemote 为正文及附件单个提交写入，同时保留 Echo 原单文件接口兼容。对每个预期文件核验指定提交中的 blob/内容；二进制使用字节摘要，不能按 UTF-8 文本核验。
- 首期拟限正文 256 KiB、单附件 10 MiB、单次附件合计 25 MiB；阶段一实测资源后固定在接口和 UI，超限明确拒绝并保留草稿，不隐式截断或自动接入 LFS。
- 远端文件被修改、移动或删除后进入冲突，不覆盖、不复活；用户可显式另存。并行 Echo 提交产生分支冲突时重新读取并安全重试，禁止强推。
- 同一提交丢回执或进程重启时恢复持久 attempt，避免重复提交。GitHub 与服务器不能做跨系统事务，必须采用可重试状态转换与核验补偿。

### 5. 自动清理是独立验收关卡

清理必须同时满足：该快照正文和全部附件已核验到 GitHub；当前源版本仍匹配；没有未提交的新正文/附件；所有编辑会话已明确安全结束；距最后活动超过 120 秒；没有未解决错误。

特别约束：心跳过期只能说明连接状态未知，不能证明用户结束编辑。失联、手机后台休眠或服务重启造成会话不确定时，禁止自动清理；等待恢复会话明确释放或用户处理。阶段一需实现不含正文的持久会话/不确定状态，避免重启把所有会话当成关闭。打开编辑和开始清理需互斥；迟到请求用 fencing token 拒绝。仅在接入程序加锁无法约束 Memos 原生写入，不算通过。

清理顺序：原子校验并标记退休 → 可恢复地删除正文与自有附件 → 核验完成 → 清掉投递快照副本，仅留元数据。故障时可续跑，不恢复已退休源记录。共享附件必须核查引用，禁止连带删除其他笔记内容；不传播删除到 GitHub/电脑。

清理范围包括 Memos 数据库、附件存储、Echo 队列、临时下载与应用缓存；日志不记录正文。归档不等于清理。数据库 WAL、空闲页及备份的残留与保留周期须单独核实，不能把逻辑删除宣传为安全擦除。不对临时正文做无限期快照备份；失败与未投递内容不得按年龄清除，应告警请求处理。

若无法在固定版本中落实上述原子检查与会话保护，停止自动清理阶段，仅保留合成数据验证结果，不以「延迟更久再 DELETE」替代，也不以默认长期留存真实内容绕过用户要求。

### 6. 目录、配置与上游维护

以下目录仅在计划确认和阶段一选型后创建：
- upstream/memos/：固定上游源码与许可证、本地补丁和来源说明；不保留嵌套 Git 历史，不含数据库、凭据、构建产物。先记录 tag、commit 与构建工具链，升级必须重跑协议与清理测试。
- src/server/memos/：接入适配、状态转换与恢复逻辑；保持 Echo 现有接口可用，不引入通用工作流平台。
- tests/memos/：合成测试数据、契约/并发/恢复用例；运行产物写系统临时目录，按授权清理，不误删工作区文件。
- deploy/memos/：不含凭据的容器与配置模板；运行数据路径必须在项目外独立目录。部署域名、资源限额和存储位置在部署审批前确定。
- docs/setup/memos.md：固定版本、启动方法、验证证据、运维与回退说明；本轮尚不创建。

新增入口建议使用 Memos 原生登录、私有可见性、关闭开放注册和公开分享；这是待确认的新增服务策略，不恢复 Echo 已取消的网页登录鉴权。保留 HTTPS、Host、同源写入与适用的 WebSocket Origin 校验。GitHub token 仅由服务端使用；服务间凭据另设最小权限，不向浏览器下发。新增投递及清理开关默认关闭，不能因 Echo 当前已开启同步而自动启用 Memos。

### 8. 验收矩阵与执行命令

- 输入：空白不落盘、中文组合输入、连续点击、纯附件、同秒创建、刷新与手机后台切换；无显式操作不得上传正文/附件。
- 可靠性：请求超时、重复/乱序通知、分页边界、GitHub 不可用、提交已成功但回执丢失、进程在各检查点崩溃；失败内容保留，可幂等恢复。
- 冲突：两台设备编辑、投递 A 后出现 B、远端移动/改写/删除、Echo 与 Memos 同时提交；不覆盖新版本或用户整理结果。
- 清理：打开编辑器同时触发清理、会话失联超过 120 秒、重启丢连接、清理中断、旧页面迟到保存；不误删、不复活。
- 附件：缺失/失败/超限/共享引用/路径穿越/二进制一致性；离开 Memos 后 Obsidian 仍可完整阅读正文与图片。
- 安全与运维：私有访问、越权读取/投递、服务凭据隔离、日志无正文、数据目录位于项目外、原 Echo 与既有服务无回归。
- 实施后运行 npm run typecheck、npm test、npm run build、npm run test:browser；固定 Memos 版本的 Go/前端检查在 P1 依据其构建配置列入 todo。新增界面按 DESIGN-LANGUAGE.md 及 ss-review 验收。本轮仅文档修改，执行 git diff --check 和范围审查，不运行应用测试冒充功能验证。

### 9. 回退、环境和授权

回退先关闭 Memos 新投递和清理入口，保留未完成队列与临时内容，用户继续使用原 Echo；不得直接删除容器卷。回退时检查在途提交并保留其核验状态。数据库升级需要升级前可恢复方案，未经验证不能只降级镜像。已进入 GitHub/电脑的内容不回滚或删除。

环境现状：普通沙箱执行在启动阶段报 setup refresh had errors；提权后的只读 PowerShell 命令可运行，已核实项目可读。当前仅有可用执行通道，不代表沙箱根因已修复。不为本任务擅自重装工具链或改系统设置；需要时对具体命令申请权限。

确认本计划后可开展本地代码实现与合成数据验证；系统配置、全局依赖安装、数据库迁移、凭据配置、真实 GitHub 写入、生产部署及真实内容删除仍遵循专项授权。新 Memos 登录策略、显式提交按钮及原生手动保存的语义随本节一并确认。正式部署前需确定域名和真机验收设备，不阻塞前期 mock/本地开发。
